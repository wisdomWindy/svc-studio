# ADR-003：资产与离线策略（签名清单 + sha256 + 断点续传 + 本地导入）

- 状态：**已接受**
- 关联：spec F-03、§13；PRD §5.3；compliance §1、§6

## 1. 问题

上游**不含任何模型权重**（contentvec / rmvpe / nsf_hifigan / G_0 / D_0 / diffusion model_0）。产品必须让用户在离线机器上把这些东西放到位，并且能判断"这个文件是不是我要的那个"。

## 2. 决策

**清单驱动 + 内容寻址校验 + 三条获取通道（离线导入 / 直连下载 / 镜像），全部以 sha256 为准。**

1. `assets/manifest.json`：每个资产声明 `kind, key, files[{path,size,sha256,urls[]}], license_note, source_note`；附 `manifest.sig`（Ed25519），公钥内置于应用。
2. 状态机：`missing → downloading → verifying → ready`，异常 `corrupt`。
3. 校验规则：**文件大小 + sha256 双校验**；只要 sha256 不符即 `corrupt`，禁止"忽略并使用"。
4. 离线导入：选目录 → 按 `文件名+大小` 匹配 → 校验 → **复制（不是移动）** 到资产目录 → 原子改名。
5. 下载：HTTP Range 断点续传；重试 3 次指数退避；镜像按清单顺序切换。
6. 安装包**不含任何第三方权重**（合规 + 体积）。

## 3. 备选与否决

| 备选 | 否决理由 |
| --- | --- |
| 直接写死上游 URL，不建清单 | 上游 README 的链接会失效（HF/box/github release 都可能变）；且无法表达"这个文件属于哪个编码器" |
| 只校验大小 | 截断文件与完整文件可能同大小（稀疏/填充）；1 字节篡改检测不出来（B4 明确要求） |
| 内置权重 | 授权不清（B3/合规 §7 阻断条件）；安装包 +4GB |
| 把权重放项目内 | 一个权重被 10 个项目各存一份（+40GB）；且模型登记引用会跨项目失效 |
| 首次启动强制联网下载 | 违反"全离线"目标；干净内网机器直接不可用 |

## 4. 关键细节

- **资产是全局的**：`%LOCALAPPDATA%\SVCStudio\assets\<kind>\<key>\`，项目只记录"用了哪个版本"。
- **清单签名失败 = 只读模式**：仍可用已就绪资产，但禁止下载/导入（防止被篡改成恶意 URL）。
- **许可与来源提示**：每个资产卡显示 `license_note`（例如"contentvec: MIT，来自原作者"），导入第三方权重时提示"确认授权"。
- **磁盘预检**：导入前算 `总字节 × 1.1`，不足直接拒绝（SVC-1006），不留半个文件。
- **修复**：`corrupt` 资产的"修复"= 重新下载或重新导入，不做"忽略"（除诊断模式）。

## 5. 后果

- 正面：离线可用；篡改可检测；跨项目复用；安装包可控。
- 负面：用户必须自己搞到权重（这是上游的合规现实，不是产品缺陷）；首次使用有一步"导入资产"的额外操作。
- 监控：doctor 的 3 个权重检查项直接读资产表，不重复扫盘。
