> 结论：**无阻断性歧义**，5 条产品决策给出默认值（见 §7），默认值不阻塞 PRD 评审。

## 2. 能力边界判定

- 上游是 **SVC**：输入是音频，输出是同内容、不同音色的音频。没有文本输入，没有声码器直出文本的能力。
- 因此"自动训练和推理音频"= 自动完成 **数据 → 特征 → 模型 → 转换**，而不是"输入文字出语音"。
- 产品命名、空态文案、帮助都必须避免"文字转语音""AI 配音""TTS"等词，否则用户预期从第一天就错。

## 3. 责任划分（本地三层，无服务端）

| 层 | 归属 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 呈现层（Tauri WebView2 + React） | 产品自有 | 渲染、状态展示、参数收集、校验反馈 | 任何 >16ms 的同步阻塞、直接读写大文件、直接调 torch；无文件/进程权限 |
| 核心层（Rust） | 产品自有 | 任务状态机、SQLite、资产校验、文件原子写、进程树管理、IPC | 加载 torch、做推理、在 IPC handler 里同步长操作 |
| 执行层（Python worker） | 产品自有 + 上游脚本 | 运行 resample/preprocess/train/inference 等上游入口，回传结构化事件 | 直接操作 UI、直接写数据库 |

结论：本产品**没有服务端责任**，但"编排层"承担了传统后端的职责（任务、事务、资源调度），必须按后端标准做错误处理与幂等。

## 4. 歧义消解（写 PRD 前必须定死的 6 件事）

| # | 歧义 | 判定 | 依据 |
| --- | --- | --- | --- |
| A1 | "自动训练"是"一键到底"还是"每步可停"？ | **两者都要**：默认一键，专家模式可单步；任何一步失败都停在原地可修复 | 目标用户不会调参，工作室需要可控 |
| A2 | "暂停训练"能否真的暂停？ | 不能。上游只能停止+续训 | `train.py` 无 pause、checkpoint 按 eval_interval |
| A3 | 推理的 F0 用哪个？ | 默认跟随训练时记录的值，可覆盖但给出跑调警告 | 上游训练默认 rmvpe、推理默认 pm（C-13） |
| A4 | 是否允许用户直接改 config.json？ | 允许，但必须过 Schema；暴露高频字段做表单，其余走"高级 JSON"并做 diff 预览 | 上游参数多，全表单化不现实 |
| A5 | 项目 vs 数据集 vs 模型的关系 | 1 个项目 = 1 个工作区 = N 个数据集版本 + M 次训练 + K 个模型 | 上游所有路径都是相对的，工作区是唯一干净隔离手段 |
| A6 | 安装目录能否放项目数据？ | 可以放安装目录下的数据目录（如 `projects\`），但程序子树（app/runtime/assets）只读；默认仍落用户目录 | 真实硬约束只有"升级覆盖/卸载清理"；Program Files 下先做写入探测，失败按权限错误处理 |

## 5. 需求来源标注规则

- `[SRC]` 直接来自上游 README/代码的事实；
- `[SCENE]` 来自场景方法论（硬件、阈值、门禁）；
- `[DEC]` 产品决策（本条 PRD 的默认值，可被用户否决）；
- `[DERIVED]` 由上述三者安全推导（例如"必须锁单卡"来自 train.py 的 spawn 行为）。

PRD 中的每条约束都带这四类标签之一，禁止出现无标签的"行业惯例"。

## 6. 冲突与裁决

| 冲突 | 裁决 | 理由 |
| --- | --- | --- |
| 音质（浅扩散/增强）vs 速度（RTF ≤1.5） | 默认关闭浅扩散与增强；开启时在 UI 显示预估耗时并允许"只此一次" | 基线机 6GB，浅扩散显著加时；默认值必须保证 F3 达标 |
| 数据量（≥30min 建议）vs 用户只有 10min | 允许豁免但强制风险确认，训练报告标注"低数据量" | 阻断会赶走用户，不阻断会产出垃圾模型 |
| 全自动 vs 可解释 | 自动给出推荐值，但每个推荐值旁显示"为什么"（显存/最短切片/编码器） | 用户不信任黑箱参数 |
| 6GB 显存 vs 上游默认 batch_size=6 | 按显存探测改写 batch_size，默认 6GB→2 | config 模板默认 `batch_size=6` 在 6GB 上极易 OOM（E1） |

## 7. 待用户确认的 5 个决策（均带默认值）

| ID | 决策 | 默认 | 若否决的影响 |
| --- | --- | --- | --- |
| Q-01 | 暂停=停止+续训的语义 | 接受 | 需要改上游训练循环，工作量 +2 周且更易崩 |
| Q-02 | 应用内是否提供官方资产直链下载 | 提供，默认关闭需点击 | 只剩离线导入，J2 变成唯一路径，体验变重 |
| Q-03 | ONNX 导出是否首发 | 首发（实验性） | 模型库少一个入口，不影响主线 |
| Q-04 | 动态声线混合是否含时间轴编辑器 | 基础版（表格+试听） | 全拖拽编辑器 +1.5 周 |
| Q-05 | 是否内置 ffmpeg | 内置 | 需用户自装，增加 B2/G2 的错误面 |

## 8. 风险登记（进 PRD §14）

1. fairseq 0.12.2 与新版 torch 的兼容性（高）；
2. PyInstaller 打包 torch/CUDA/cuDNN 的 DLL 完整性（高）；
3. 上游相对路径与"项目工作区"的耦合（中，靠 cwd + 桥接层解决）；
4. 中文/空格/长路径下的 fairseq 与 ffmpeg 行为（中）；
5. 6GB 显存下扩散训练（duration/batch）几乎不可用（中，降级为"不支持"而不是硬撑）；
6. 上游归档后无安全更新（低，vendored 锁定）。
