# 合规评估：SVC Studio（基于 so-vits-svc 4.1-Stable）

- 结论：**可分发（Conformant-with-obligations）**。前提是随包提供完整对应源码、保留使用规约确认门禁、不内置任何第三方模型权重。
- 评估依据：AGPL-3.0 全文（上游 `LICENSE`）、上游 `README_zh_CN.md` 的「声明」「使用规约」「法律条例参考」、`requirements.txt` 的第三方依赖集合。

## 3. 数据集与真人声音

- **数据集授权**：导入数据集时必须勾选"我确认对该素材拥有训练与转换所需权利"，未勾选不允许进入预处理；声明写入 `consents` 表（含时间、数据集指纹、文案版本）。
- **真人声音**：产品只做告知与确认，不做授权代办、不做真伪背书。首启与每次训练前均展示"禁止未经许可克隆他人声音"。
- **声纹敏感性**：声音样本在多数司法辖区可识别到个人，按敏感个人信息处理：仅本地存储、不上传、不进入诊断包、日志中不记录音频内容。
- **法条引用**：随帮助文档附《民法典》第 1019/1024/1027 条原文（与上游 README 一致），不做法律意见。
- **未成年人**：首启规约中明确不得用于未成年人声音的未经授权克隆。

## 4. 隐私与离线

- 默认零联网、零遥测、零崩溃上报；`doctor`、`assets`、更新检查全部本地执行。
- 唯一的联网动作是"用户点击下载资产"，且请求只发往清单中登记的 URL；请求日志写入本地，不含音频。
- 诊断包（B5）内容白名单：版本、OS/驱动、doctor 结果、日志尾部 2000 行（脱敏路径）、配置快照。**禁止**包含音频、`.soft.pt`、`.f0.npy`、模型权重；打包前做一次内容扫描并在 UI 展示清单。

## 5. 产物溯源

- 每次导出写入：`model_sha256`、`model_step`、`config_sha256`、`params_json`（规范化后 sha256 + 原文）、`dataset_fingerprint`、`app_version`、`created_at`。
- 载体：FLAC 默认写入 Vorbis comment；WAV 写 LIST/INFO；同时生成同名 `.json` sidecar（防止播放器丢弃标签）。
- 该元数据用于"同参数重跑可复现"与"侵权追溯"，不包含用户身份信息。

## 6. 第三方依赖合规

- 依赖清单以 `requirements.lock.txt` 为准，逐项记录许可证，生成 `licenses/third-party.csv` 与 `SBOM.json`（CycloneDX 1.5）。
- 重点风险项：`fairseq==0.12.2`（MIT）、`torch/torchaudio`（BSD-3）、`faiss-cpu`（MIT）、`librosa`（ISC）、`praat-parselmouth`（GPL-3.0 — **注意**：GPL 组件以独立进程/独立包形式使用，不静态链接进我们的代码；若最终打包进同一二进制需重新评估）。
- 发布门禁：`licenses/third-party.csv` 中存在 `UNKNOWN` 或 copyleft 冲突时阻断发布。

## 7. 不可分发的情形（阻断条件）

出现以下任一情况，产品必须转为"内部自用工具"，不得对外分发：

1. 无法提供与本版本二进制严格对应的源码；
2. 内置了来源不明或授权不清的模型权重；
3. 打包方式导致 GPL 组件（如 parselmouth）与自有代码形成单一作品且不满足 GPL 条款；
4. 产品文案暗示可"一键克隆任意真人声音"或提供授权背书。

## 8. 门禁证据（G0 / A2 / A3）

- `scope.yaml` 的 `out` 含 "TTS" 与 "内置任何第三方模型权重"。
- 首启流程：`SVC Studio 使用规约 v1` → 4 个必选勾选（AGPL 许可、使用规约、数据集授权、真人声音告知）→ 写 `consents` 表（`app_version`, `doc_version`, `accepted_at`, `hash`）→ 训练入口解锁。
- 安装包 `licenses/` 目录清单与哈希在 S9 阶段产出，纳入 H1/A3 证据。
