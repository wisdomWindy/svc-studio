## 1. 背景与问题

so-vits-svc 4.1-Stable 是一个能力很强、但**使用门槛极高**的歌声音色转换（SVC）框架。它把能力给到了命令行：

```
resample.py → preprocess_flist_config.py → preprocess_hubert_f0.py → train.py → inference_main.py
```

一个普通创作者要跑通这条线，必须同时解决：Python 3.8.9 环境、torch/CUDA 版本匹配、fairseq 编译、六个以上模型权重的来源与放置、切片的时长约束、F0 与编码器的选择、config.json 的十几个参数、显存与 batch_size 的匹配、训练中断后的恢复、推理参数的互斥关系。

**这些不是"知识问题"，是"产品问题"**：每一步失败都只给一行英文报错，用户不知道是权重没放对、显存不够、还是切片太长。结果是绝大多数人卡在第三步之前。

本产品的机会：把这条线做成**有门禁的产线**——每一步都有前置检查、有可读的失败原因、有可恢复的中间状态。

## 2. 产品定位

> **一句话**：让一台没有 Python 的 Windows 电脑，从装好到听见第一条转换结果，不需要命令行、不需要查教程；中途任何一步断了，都能接着来。

**是什么**
- 一个本地 Windows 桌面应用（离线优先），内置运行时与上游代码；
- 一个**流水线编排器**：数据 → 预处理 → 训练 → 推理，每段都有门禁、产物校验与恢复点；
- 一个**参数专家系统**：按显存、编码器、最短切片自动给出可解释的推荐值，并拦住会必然失败的输入。

**不是什么**
- 不是 TTS：没有文本框，不上传文字，不生成语音。上游 README 明确"本项目无法实现 TTS，与 VITS 模型不通用"。
- 不是模型分发平台：不内置任何权重，不提供"下载即用"的成品音色。
- 不是云端服务：不训练、不推理、不收集任何数据。
- 不是"一键克隆任何人"：只做工具，不做授权背书。

## 3. 用户与场景

### 3.1 Persona

**U1 个人创作者 · 小满**
有 40 分钟自己唱的歌（手机录的，有底噪），一台 GTX 1660 的台式机。装过 Python，被 fairseq 劝退过两次。诉求：把 A 歌换成自己的音色，能听就行；不想学参数。
- 关键情绪：怕"跑了一晚上发现白跑"。
- 设计含义：**任何长任务都必须先有冒烟**；任何失败都必须告诉他"下一步点哪里"。

**U2 工作室 · 老陈**
三个人共用一台 3060 机器，一周交付 20 条。诉求：批量、参数复用、出错能查、模型别删错。
- 关键情绪：怕"不知道哪条失败了""参数改了什么记不住"。
- 设计含义：**任务中心 + 参数快照 + 模型占用检查**是刚需，不是加分项。

| 场景 | 起点 | 终点 | 关键约束 |

> 每条需求都有 ID（`REQ-xxx`）与验收映射，详情与 Given/When/Then 见 [requirements.md](requirement-splitting/requirements.md)。本节写"行为与规则"。

### 5.1 项目与工作区（基础设施；验收落点 G6 路径健壮性 / H4 卸载）

**概念**：项目 = 一个工作区目录 = 一条独立的 so-vits-svc 产线。所有上游脚本都使用相对路径（`dataset_raw/`、`dataset/44k/`、`configs/`、`filelists/`、`logs/44k/`、`raw/`、`results/`），因此**工作区就是隔离手段**。

```
<项目根>/                      任意可写目录；默认 %USERPROFILE%\SVCStudio\projects\<slug>
├─ project.json                项目元数据（名称/说话人/编码器/F0/素材类型/创建时间）
├─ configs/                    config.json、diffusion.yaml
├─ filelists/                  train.txt、val.txt
├─ dataset_raw/<speaker>/      用户原始音频
├─ dataset/44k/<speaker>/      清洗后音频 + 上游产物（.soft.pt/.f0.npy/.spec.pt[/.vol.npy/.mel.npy/.aug_*]）
├─ logs/44k/                   G_*.pth、D_*.pth、events/、train.log
├─ logs/44k/diffusion/         扩散模型与 config.yaml
├─ raw/                        推理输入暂存（上游约定，每次批次执行前清空）
├─ results/<批次>/             推理输出，按批次分目录（含 report.json）
├─ quarantine/                 被切片/剔除的原文件
├─ reports/                    qc_report.json、train_report.json、inference_report.json
└─ .svcstudio/                 lock、manifest、fingerprints、tmp（原子写中转）
```

**规则**
1. 项目根可以是**任意用户可写目录**：默认 `%USERPROFILE%\SVCStudio\projects\<slug>`；允许换盘符、U 盘、网络盘（网络盘给"IO 慢，训练可能变慢"警告）、含中文与空格的路径。
2. **唯一的硬禁止**是安装目录里的程序子树（`app\`、`runtime\`、`assets\`、`configs_template\`）：这些由安装器管理、升级时整体覆盖，写进去必丢。安装目录下的**数据目录**（如 `projects\`）不属于程序子树，允许使用。
3. 若用户把项目建在安装目录内（含 Program Files）：创建前给出"升级/卸载可能影响数据"的确认；Program Files 下先做写入探测，失败则按 SVC-7001 阻断，并给"换到用户目录 / 便携目录"两个按钮。
4. 便携模式：整个应用可解压到任意目录，数据默认落在同级 `SVCStudio-data\`，实现"程序放哪都行、数据跟着走"。
5. 路径长度 >200 字符时在创建/导入时警告（Windows MAX_PATH 风险），但不阻断。
6. 同一项目同一时间只允许一个写任务：`.svcstudio/lock` + SQLite 事务双保险；第二个任务进入 `queued`。
7. 删除项目必须二次确认，且要求输入项目名；删除范围 = 工作区目录（含 `dataset_raw` 内的副本）+ 数据库记录；用户从外部路径导入的原件不受影响。
8. 工作区迁移（换盘）通过"重新定位"完成：更新路径 → 校验关键目录 → 旧路径标记不可用。

**卸载行为**：卸载器只处理程序文件、注册表、服务与计划任务（H4 的残留口径）；若检测到安装目录内存在用户数据，卸载向导单独询问"保留（默认）/删除"。默认保留，因此把数据放在安装目录的用户不会因卸载丢数据——代价是这些文件会留在原地。


### 5.2 环境自检 doctor（REQ-004）

**时机**：首次启动、每次进入训练前、用户手动点击、任务失败后的"重新检查"。
**输出**：UI 列表 + `SVCStudio.exe --doctor --json`（结构化，供诊断包与自动化；对应 B1 的验证方式）。

| # | 检查项 | 通过条件 | 失败时的动作 |
| --- | --- | --- | --- |
| 1 | Python 运行时 | 内置 3.8.9 可启动，`sys.version_info[:3] == (3,8,9)` | 修复安装；报告损坏文件 |
| 2 | torch | 可导入，版本与轮子清单一致 | 给出"重装运行时"入口 + 版本矩阵 |
| 3 | CUDA | `torch.cuda.is_available()` 为真且 `torch.version.cuda` 与驱动匹配 | 展示 torch CUDA 版本与驱动版本对照表 |
| 4 | GPU 与显存 | 能枚举到 ≥1 块 NVIDIA GPU，显存 ≥6GB | 列出实际型号/显存；<6GB 时训练降级为"不可用" |
| 5 | ffmpeg | 内置 ffmpeg 可执行且 `-version` 成功 | 内置缺失=安装损坏；走修复 |
| 6 | 磁盘余量 | 项目所在盘 ≥20GB 可用 | 显示当前余量 + "换盘"入口 |
| 7 | 语音编码器权重 | 与项目所选编码器匹配的文件存在且 sha256 通过 | 跳资产中心对应条目 |
| 8 | F0 权重 | rmvpe/fcpe 按所选预测器存在且校验通过 | 同上 |
| 9 | 声码器 nsf_hifigan | 目录下 4 个文件齐全且校验通过 | 同上 |

> 附加告警项（不计入上述 9 项）：底模 `G_0/D_0` 缺失仅告警——上游允许从零训练，只是收敛更慢。

**要求**
- 每项三态：`pass` / `warn` / `fail`，并给"一句话原因 + 一条可复制的修复动作"。
- 检查总耗时 ≤5s（除 sha256 首次校验），结果缓存 10 分钟，权重变更即失效。
- 只要存在 `fail` 且属于训练必需项，训练按钮置灰，悬停显示具体原因。

### 5.3 资产中心（REQ-005、REQ-006）

**资产分类**：语音编码器（按所选）、F0 预测器、声码器、底模（G_0/D_0）、扩散底模（model_0.pt）、whisper 系列（可选）。
**状态机**：`missing → downloading → verifying → ready`，异常分支 `corrupt`。

**规则**
1. **不内置任何权重**。清单只描述"需要什么、放哪里、sha256 是多少、来源在哪"。
2. 离线导入：选目录 → 按文件名+大小匹配清单 → 校验 sha256 → 原子移动进 `pretrain/`。允许"文件名不同但用户手动指定映射"。
3. 断点续传：HTTP Range；失败重试 3 次（指数退避）；镜像按清单顺序切换。
4. 校验失败：文件标记 `corrupt`，UI 明确"文件可能被截断或被修改"，给"重新下载/替换文件/忽略（不推荐）"三个选项；忽略需二次确认且训练入口保持阻断。
5. 清单签名：`manifest.json` 附 `manifest.sig`（Ed25519），启动时校验清单本身未被篡改；公钥硬编码在应用内。
6. 资产与项目的关系：资产是**全局**的（跨项目复用），路径可配置；项目只记录"用了哪个版本的编码器/声码器"。

**诊断包（REQ-006）**：`SVCStudio-diagnostics-<时间>.zip`，含 `doctor.json`、`versions.json`（OS/驱动/CUDA/cuDNN/torch）、`logs/tail-2000.txt`（路径脱敏为 `<HOME>`/`<PROJECT>`）、`config-snapshot.json`、`manifest-check.json`。**白名单打包 + 打包前扫描**，绝不含音频、特征文件、模型权重。

### 5.4 数据集与 QC（REQ-007 ~ REQ-011）

**导入**
- 支持拖拽文件夹或选目录；结构必须是 `dataset_raw/<speaker>/*.wav`（允许只有一层 speaker 目录）。
- 非 wav（mp3/m4a/flac）：不静默转换，列出并提供"用 ffmpeg 转为 44.1k 单声道 wav 后导入"的一键动作（转换结果进 `dataset_raw`，原件不动）。
- 多层嵌套、空目录、隐藏文件、同名冲突：逐条列出问题与建议，不崩溃、不部分导入（要么全量校验通过，要么整体回滚）。

**QC 报告（7 项指标 + 分布）**

| 指标 | 口径 | 阈值/展示 |
| --- | --- | --- |
| 总时长 | 所有 wav 时长求和 | <30min 告警并要求豁免（REQ-011） |
| 单条时长分布 | min / p50 / p95 / max + 直方图 | 任何一条 >30s 视为阻断（whisper 系硬约束是 <30s；其余编码器也统一按 30s 卡，留显存余量）；>15s 进待处理 |
| 采样率 | 分布 | 非 44100 计入待处理（可一键重采样） |
| 声道 | 分布 | 非单声道计入待处理 |
| 静音比 | 低于 -40dBFS 的帧占比 | >20% 阻断（说明素材有大量空白） |
| 削波 | 连续 ≥3 个样本达满刻度的片段占比 | ≥0.1% 阻断 |
| 响度 | 整体 RMS dBFS + 每条分布（`method=rms`，不引 pyloudnorm） | 仅展示；跨度 >12 dB 提示"响度不一致" |

> 口径必须可复核（时长/采样率/声道与 ffprobe 抽样一致，误差 ≤1%），这是 C2 的验收方式。响度用 RMS 而非 LUFS：不引入额外依赖，口径写在报告里。

**切片（REQ-009）**
- 目标 5–15s；静音阈值 -40dB；最小间隔默认 300ms，可切"陈述/歌唱/强切分"三档（300 / 100 / 50ms）。
- 切片命名 `<原名>_<序号>.wav`；原文件移入 `quarantine/`（不是删除），切片记录写 manifest。
- 幂等：重复执行时已切过的文件跳过（以 `<原名>` + 源文件 sha256 为键）。
- 切片后立即重算时长分布，超长/超短进"待处理清单"，附"重切/剔除/保留"三个动作。

**格式统一（REQ-009）**
- 44100Hz、单声道、16-bit PCM；`trim(top_db=40)` 去首尾静音。
- 峰值保护：默认把峰值限制到 **-1 dBFS**（而不是上游的 0 dBFS 归一化）；高级选项可关（等价 `--skip_loudnorm` 行为）。
- 可选降噪：ffmpeg `afftdn`，默认关闭；文案明确"重度降噪会伤音色，建议外部工具"。

**门禁（REQ-010）**
- 阻断项：单条 >30s、采样率/声道未统一、静音比 >20%、削波 ≥0.1%、存在 0 字节/无法解码文件。
- 阻断项未清零 → 预处理按钮置灰，点击显示"还有 N 项阻断，去处理"。
- 豁免：仅"总时长不足"可豁免（REQ-011），需勾选风险说明并记录到 `consents`；训练报告打 `low_data=true` 标记。

### 5.5 预处理与配置（REQ-012 ~ REQ-015）

**三步链路**（顺序固定，每步是一次独立子进程）

| 步 | 上游命令 | 关键参数 | 产物 |
| --- | --- | --- | --- |
| 1 | `python resample.py` | `--sr2 44100`、`--skip_loudnorm`（关闭峰值处理时） | `dataset/44k/<spk>/*.wav` |
| 2 | `python preprocess_flist_config.py` | `--speech_encoder <enc>`、`--vol_aug` | `filelists/train.txt`、`filelists/val.txt`、`configs/config.json`、`configs/diffusion.yaml` |
| 3 | `python preprocess_hubert_f0.py` | `--f0_predictor <f0>`、`--use_diff`、`--num_processes N` | `.soft.pt` `.f0.npy` `.spec.pt`（+`.vol.npy`/`.mel.npy`/`.aug_mel.npy`/`.aug_vol.npy`） |

**要求**
1. 用户能看到**即将执行的完整命令与参数**（可复制），不做黑箱。
2. `num_processes` 推荐：6GB→1、12GB→2、24GB→4（原因：每个 worker 都会把语音编码器加载到 GPU，进程数直接吃显存）。允许 0=CPU 核数，但给出 OOM 警告。
3. 每步写 `preprocess_manifest.json`：命令、参数、开始/结束时间、exit code、产物计数、逐文件 sha256（可只存抽样）。
4. 断点：任一步失败/取消，已完成的文件不重做（上游脚本本身幂等，产品只需正确传递并跳过已完成步）。
5. 单文件重跑：从产物差异清单点"重跑这一条"。
6. 产物一致性校验（REQ-013）：以 `dataset/44k/<spk>` 下 `.wav` 数量为基准，要求 `.soft.pt`/`.f0.npy`/`.spec.pt` 数量一致；`--use_diff` 或 `vol_embedding` 时额外校验 `.vol.npy`；`--use_diff` 时再校验 `.mel.npy`/`.aug_mel.npy`/`.aug_vol.npy`。差异 >0 时列出缺哪个文件的哪类产物。

**配置编辑器（REQ-014）**
- 表单字段（带范围、默认值、影响说明）：`batch_size`、`epochs`、`learning_rate`、`fp16_run`、`half_type`、`keep_ckpts`、`all_in_mem`、`segment_size`、`vocoder_name`（nsf-hifigan / nsf-snake-hifigan）、`vol_aug`、`use_automatic_f0_prediction`。
- `diffusion.yaml` 字段：`duration`、`batch_size`、`timesteps`、`k_step_max`、`cache_all_data`、`cache_device`、`amp_dtype`。
- **硬断言（保存即拦截）**：
  - `diffusion.duration < min(切片时长)`，否则报"duration=3.0s 大于最短切片 2.4s，扩散训练会崩"；
  - `k_step_max < timesteps`，且 `k_step_max=0` 才能用于纯扩散推理；
  - `batch_size ≥ 1`；`keep_ckpts ≥ 0`；`epochs ≥ 1`。
- 高级模式：直接编辑 JSON/YAML，保存前做 Schema 校验 + diff 预览（左旧右新），非法即拒绝并定位到行。
- 所有修改自动备份为 `configs/.history/config-<时间戳>.json`，可回滚。

### 5.6 训练（REQ-016 ~ REQ-023）

**参数推荐（REQ-016，带解释）**

| 显存 | 主模型 `batch_size` | 扩散 `batch_size` | 扩散 `duration` | 预处理进程 |
| --- | --- | --- | --- | --- |
| 6GB | 2 | 8 | 2.0s | 1 |
| 8GB | 3 | 12 | 2.5s | 2 |
| 12GB | 6 | 24 | 3.0s | 2 |
| 24GB | 10 | 48 | 4.0s | 4 |

> 表是**起点**不是承诺：卡片上写明"依据显存与最短切片估算，实际以 OOM 自愈为准"。用户可改，越界（1..32）被拦截。

**冒烟训练（REQ-017）—— 这是产品最关键的"防白跑"设计**
- 目标：100 步内证明四件事——loss 是有限值、checkpoint 能落盘、能续训、事件文件可读。
- 实现方式（重要）：**不伪造训练**，而是复制一份临时 config 后启动真实 `train.py`，并让它写进独立的 `logs/_smoke/`（`-m _smoke`），不污染正式模型目录：
  1. `eval_interval = 50`、`log_interval = 10`、`keep_ckpts = 2`（保证 100 步内落盘）；
  2. 监听日志/事件中的 `step`，达到 100 时优雅结束进程；
  3. 校验 `logs/_smoke/G_100.pth`（或最近 ≥50 步的 checkpoint）存在且可 `torch.load`；
  4. 记录峰值显存、step 速率、首末 loss。
- 冒烟产物**不登记**为模型，只保留最近一次供排查。
- 失败处理：loss 为 NaN/Inf → 立即停止并给数据/配置诊断；OOM → 触发降档重试（REQ-021）；8 分钟未到 100 步 → 停止并报告瓶颈（E2 门禁为 ≤10 分钟完成）。

**长训（REQ-018）**
- 进度：`step / total_steps`，`total_steps = epochs × ceil(train_files / batch_size)`；ETA 用最近 50 步的滚动步速。
- 曲线：`loss/g/total`、`loss/d/total`、`loss/g/mel`、`loss/g/kl`、`loss/g/fm`、`loss/g/lf0`、`learning_rate`、`grad_norm_d/g`。数据源优先 TensorBoard event 文件（`logs/44k/events/`），日志仅做文本。
- 显存：每 5s 采样一次（pynvml），记录峰值与均值。
- checkpoint 列表：步数、文件大小、时间；可"设为推理默认"。
- 日志：流式追加到 UI（批量刷新 100ms，避免卡顿），支持按等级/关键词过滤，可导出。

**停止 / 续训（REQ-019、REQ-020）**
- UI 只有两个动作：**停止**与**取消**（语义见 §8 文案规则）。
  - 停止 = 让训练进程优雅退出；续训 = 重新执行 `train.py`，它会自动加载最新 checkpoint（上游行为）。
  - 取消 = 立即终止，任务记 `cancelled`；已落盘的 checkpoint 保留在磁盘，但不会被登记为可用模型。
- 停止后 UI 必须显示："已停止在第 N 步；下次从这里继续；最多丢回最近一次保存（每 800 步）"。
- **新建训练 vs 续训**：`train.py` 启动即自动加载 `logs/44k` 最新 checkpoint，因此 UI 必须二选一——新建训练时若发现未登记 checkpoint，必须让用户选择"归档旧模型"（移到 `logs/archive/<时间>/44k/`）或"改为续训"，**禁止静默续训**。
- 取消/停止都必须：5s 内终止整个进程树（Windows Job Object），并校验显存回落（`nvidia-smi` 对比）。

**OOM 自愈（REQ-021）**
- 识别：stderr/日志出现 `CUDA out of memory` / `OutOfMemoryError`。
- 动作：把 `batch_size` 减半（下限 1）、扩散再降 `duration` 一档，重启一次，并在任务里记录 `auto_downgrade: [{from, to, reason}]`。
- 只重试一次；再失败则停止，给结构性建议（换更短切片/关 `all_in_mem`/关扩散/升级显存）。
- 用户必须能看到"降档发生了"，不能静默改参数。

**扩散 / 聚类 / 索引（REQ-022，P1 可选能力）**
- 扩散训练：`python train_diff.py -c configs/diffusion.yaml`，产物 `logs/44k/diffusion/`；前置校验 `duration < 最短切片`。
- 聚类：`python cluster/train_cluster.py [--gpu]`，产物 `logs/44k/kmeans_10000.pt`。
- 特征检索：`python train_index.py -c configs/config.json`，产物 `logs/44k/feature_and_index.pkl`，前置要求已完成特征预处理。
- 三者都是"可选任务"，失败不阻断主模型可用性。

**模型登记（REQ-023）**：训练结束（或手动）把模型写入模型库，字段见 §5.8。

### 5.7 推理（REQ-024 ~ REQ-031）

**输入与模型**
- 模型来自模型库（已登记，含 §5.8 导入的外部模型）、其他项目的模型（只读引用）或手动指定 `G_*.pth` + `config.json`（手动指定时当场跑兼容性判定，不合格给 SVC-6005 并列出缺失键）。
- 说话人下拉来自 `config.json` 的 `spk` 映射；多说话人模型必选。
- 源音频支持拖拽、文件选择、文件夹（批量）；先转成 44.1k 单声道 wav 放 `raw/`（上游约定），保留原件。

**模型复用与批次（"训练一个音色、推理一堆音频"的正式答案）**
- 一次训练产出的是**模型**，不是"一次性任务"：同一个模型可以被无限次调用，单条、批量（一次 1–500 条）、跨天反复使用；推理只读模型与 config，不修改任何权重。
- 一个项目可以登记**多个模型**（不同 checkpoint / 不同配置 / 压缩版），推理时逐个切换；模型库是全局面板，按"来源项目"分组，所以 A 项目训的音色可以在 B 项目里直接用。
- 输出按**批次**归档：`results/<yyyyMMdd-HHmm>_<批次名>/`，批次内含输出音频 + `report.json`（参数快照、RTF、峰值、失败清单）。批次可整体"另存到"任意目录，也可删除（不影响模型）。
- 没有打开训练项目也能推理：走"独立推理工作区"（只有 `configs/`、`raw/`、`results/`），用于拿到别人的 `*.svcmodel.zip` 直接试听。
- **非本软件训练的模型**（只有 `.pth` + `config.json`）走 §5.8 的外部模型通道：能判定兼容就登记，输出落它自己的独立批次目录，不混进任何项目。
- 批次与模型解耦：删掉模型不会删掉历史批次；批次里保留参数快照与模型 sha256，重跑时若模型已删除，提示"重新指定模型"而不是静默失败。


**参数面板（完整表见附录 A）**，必须与上游 `inference_main.py` 一一对应，且默认值可解释：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `trans` 变调 | 0 | -24..+24 半音 |
| `f0_predictor` | 跟随模型训练值 | 上游训练默认 rmvpe、推理默认 pm，不一致会跑调 |
| `auto_predict_f0` | 关（歌声禁用） | 语音可开；歌声开=严重跑调 |
| `cluster_infer_ratio` | 0 | 0–1，无聚类/索引时必须为 0 |
| `cluster_model_path` | 自动 | 聚类 `.pt` 或索引 `.pkl` |
| `feature_retrieval` | 关 | 开则聚类禁用，`-cm/-cr` 语义变成索引 |
| `shallow_diffusion` | 关 | 开则增强器禁用 |
| `k_step` | 100 | 浅扩散步数 |
| `enhance` | 关 | 对少数据模型可能有益，对好模型有害 |
| `loudness_envelope_adjustment` | 1.0 | 越接近 1 越用输出响度包络 |
| `use_spk_mix` | 关 | 动态声线混合 |
| `clip` | 0（自动） | whisper-ppg 强制 25 |
| `linear_gradient` | 0 | whisper-ppg 强制 1 |
| `slice_db` | -40 | 嘈杂 -30，保呼吸 -50 |
| `noise_scale` | 0.4 | 影响咬字与音质 |
| `pad_seconds` | 0.5 | 抑制首尾异响 |
| `wav_format` | flac | 可选 wav |

**自动联动（不可绕过）**
1. 模型编码器是 whisper-ppg/whisper-ppg-large → `clip=25`、`lg=1`，输入框锁定并标注原因；
2. 项目素材类型=歌声 → `auto_predict_f0` 强制关，开关置灰 + 提示"歌声开启会严重跑调"；
3. 开浅扩散 → 增强器置灰并提示互斥；
4. 开特征检索 → 聚类模型选择器切换为"索引文件"，比例标签变为"检索混合比例"；
5. 未训练聚类/索引却填了比例 → 保存时拦截；
6. 纯扩散模式 → 需要"完整训练的扩散模型（k_step_max=0）"，否则拦截。

**执行与产物（REQ-024、REQ-025）**
- 输出命名沿用上游规则：`<源名>_<key>_<spk>_<ratio>_<sovits|sovdiff|diff>_<f0p>.<fmt>`，方便对照。
- 每次推理写 `inference_report.json`：RTF、峰值 dBFS、削波占比、输入/输出时长、参数快照（规范化 JSON + sha256）、模型 sha256。
- 输出统一 44.1kHz 单声道；写入元数据（见 compliance §5）。

**A/B 对照（体验核心）**
- 双轨播放：原声 / 输出，同步起播，音量按 LUFS 对齐；波形 + 频谱并排；可拖动同步。
- "同参数重跑"按钮：从报告里读回参数快照，一键复现。

**批量（REQ-030）**
- 队列逐条执行（不并发跑模型，避免显存争抢），单条失败隔离：记 `failed` + 错误码 + 输入 sha256，继续下一条。
- 结束状态：全成功 `succeeded`；部分失败 `succeeded_with_errors`；全失败 `failed`。
- 失败清单支持"仅重跑失败项"。

**性能（REQ-026）**：10s 输入在基线 GPU（GTX 1660 6GB）上 RTF ≤1.5；CPU 兜底模式显示实测 RTF 并提示"不可训练"。

**可复现（REQ-031）**：目标是**指标级一致**（时长差 ≤10ms、峰值差 ≤0.5dB、能量包络相关性 ≥0.99），不承诺 bit 级一致（上游含随机采样与浮点非确定性）。报告里写清这一点，避免用户误解。

### 5.8 外部模型（非本软件训练）的导入与推理

**结论**：技术上可行，且首版就做。判断依据不是"谁训的"，而是**权重结构 + config 是否与本仓库 `models.SynthesizerTrn` 对得上**——so-vits-svc 的推理只依赖 `G_*.pth` 的 state_dict 形状和 `config.json` 的结构字段，与训练来源无关。

**支持矩阵**

| 类型 | 结论 | 说明 |
| --- | --- | --- |
| 4.1 / 4.0 的 `G_*.pth`（本软件、上游 CLI、Colab、同架构 fork） | **支持** | 含 `release.pth` 压缩版（缺 `enc_q`）、FP16 半精度、单/多说话人、`vol_embedding` 变体 |
| 4.0 模型（config 缺 `speech_encoder`） | **支持（自动补齐）** | 按 `ssl_dim==256` 补 `vec256l9`，模型卡标"推断值"并可手动改；不阻断推理、不额外弹窗 |
| 只有权重、没有 config | **不支持** | 结构无法可靠反推；阻断并提示"向训练者索取 config.json" |
| 非 44100Hz 训练的模型 | **不支持** | 本管线固定 44.1k；给出"该模型采样率 X，请使用对应工具" |
| 音色聚类 `kmeans_*.pt` / 特征索引 `*.pkl` | **尽力而为** | 能加载则启用 `cluster_infer_ratio`；不能加载则禁用该参数，不阻断主推理 |
| ONNX `model.onnx` | **不支持** | 本仓库只有 `onnx_export.py`，没有 onnxruntime 推理路径；接入需另写 runner 与 MoeSS 版编码器 |
| RVC / DiffSinger / VITS-TTS 模型 | **不支持** | 架构不同，不是"配置问题" |

**导入流程（7 步兼容性判定，任一步失败即 `incompatible` 并列原因）**

1. 读权重：`torch.load(map_location="cpu")`，兼容三种封装——裸 state_dict、`{"model": ...}`、`module.` 前缀（去掉前缀后再判）。
2. 读 `config.json`：缺 `speech_encoder` 且 `model.ssl_dim == 256` → 补 `vec256l9` 并标记推断；缺 `spk` → 用 `n_speakers` 生成序号映射并警告。
3. 校验采样率：`data.sampling_rate` 必须为 44100，否则直接 `incompatible`。
4. 用该 config 实例化 `SynthesizerTrn`（**不加载编码器/声码器权重**，只建结构）。
5. 逐键比对：把权重键分成三类——`enc_q.*`（推理不需要，可缺）、推理必需键（`enc_p`/`flow`/`dec`/`emb_g`/`ref_enc` 等）、多余键。**形状不一致等同缺失**。
6. 说话人核对：`emb_g.weight` 的行数 vs `config.spk` 条目数，不一致则警告"说话人映射可能错位"。
7. 产出兼容性报告（`compat.json`）写进模型卡：`verdict`、缺失键清单、多余键数量、推断字段、所需编码器。

> 判定口径：必需键全命中且形状一致 → `ready`；只缺 `enc_q` → `ready(compressed)`；缺其他 → 判**无法识别**（弹窗 B，不进模型库，详情里列前 10 个缺失键供用户找作者核对）。
>
> 可行性证据：S2 spike 必须用 3 个异源模型各跑通一次端到端推理——(a) 4.1 上游 CLI 训的 `G_*.pth`、(b) 4.0 老模型（config 缺 `speech_encoder`）、(c) `compress_model.py` 产出的 `release.pth`；三者都要能出音频，缺一即把该项从"支持"降级为"实验性"。

**外部模型同样需要依赖资产**（这点最容易漏）：推理仍要加载与 `config.speech_encoder` 匹配的编码器权重（`vec768l12`→contentvec、`hubertsoft`→hubert-soft、`whisper-ppg`→`medium.pt`），选 rmvpe/fcpe 需要对应 F0 权重，开增强/浅扩散需要 nsf_hifigan。模型卡显示"依赖资产"及其 `ready/missing` 状态；缺资产只让**该模型**不可推理，不影响其他模型，也不阻断全局。

**输出隔离（硬规则）**

| 项 | 位置 | 规则 |
| --- | --- | --- |
| 模型本体 | `imports/<slug>/model/` | 默认**复制**进受管目录（保证路径稳定、可 sha256 校验）；可选"仅引用"（标注：源文件被移动/删除后模型失效） |
| 输入暂存 | `imports/<slug>/inputs/<批次>/` | 从项目 `raw/` 中隔离出来，不污染项目 |
| **输出** | `imports/<slug>/outputs/<yyyyMMdd-HHmm>_<批次名>/` | **每次推理单独一个文件夹**，内含音频 + `report.json` + `params.json`；可在开始前改到任意目录 |
| 模型源目录 | 只读 | **禁止**向模型来源目录写任何文件（导入后即只读引用） |
| 项目 `results/` | 不写 | 外部模型推理不混入项目产物，避免"这堆音频是哪来的" |
| 安装目录程序子树 | 禁止 | `app\`、`runtime\`、`assets\` 一律不可写 |

- 批次目录可整体移动/另存/打包；**删除模型不删已导出的批次**（批次里已留参数快照与模型 sha256）。
- 若用户把输出目录指到"模型源目录"或"安装目录程序子树" → 保存前拦截（SVC-6007），并建议默认路径。
- 外部模型**不参与**项目流水线的门禁（不需要 QC、不需要预处理），只走"选模型 → 选音频 → 参数 → 输出"。

### 5.9 模型库（REQ-023）

**作用域**：模型是**全局资产**，不是项目私有物。模型库展示所有项目产出的模型，按来源项目分组；任何项目都能引用任意模型做推理（只读）。模型可导出为 `*.svcmodel.zip`（model + config + 关联扩散/索引 + 参数说明），在另一台机器或另一个项目里导入后立即可推理。

**模型卡字段**：显示名（`项目名@step` 或外部模型的包名）、来源（`trained`/`imported`/`mixed`）、步数、文件 sha256、大小、编码器、F0 预测器、声码器、`vol_embedding`、数据集指纹与总时长（外部模型通常为空）、训练参数快照（外部模型记录"未知"）、关联产物（扩散/聚类/索引）、**兼容性报告**（`verdict` + 推断字段）、**依赖资产状态**、状态（`ready`/`compressed`/`needs_attention`/`missing`）、创建时间。

**动作**
- **导入模型（拖拽上传为主入口）**：把 1 个 `G_*.pth` + 1 个 `config.json` 拖进上传区 → 完整性检查（不通过弹「请上传模型和配置文件」）→ 复制进受管目录 → 识别（不通过弹「无法识别该模型」）。全程不改动用户源文件；详见 §5.9.1。
- 设为默认推理模型；查看训练报告；打开所在目录；
- **压缩**：`compress_model.py -c <config> -i <G> -o release.pth [--half]`，完成后新模型卡标 `compressed`，并提示"压缩后不能继续训练"。
- **ONNX 导出**（实验性）：生成临时脚本（复制上游 `onnx_export.py` 并替换 `path` 变量），产物 `model.onnx`；失败只提示不影响主流程。
- **导出包**：`<模型名>@<step>.zip`（model + config + 可选扩散/索引 + README.txt 说明来源与参数）；同格式可被上传区识别，用于跨机/跨项目复用。
- **删除**：占用检查（默认模型 / 运行中任务 / 未完成任务引用）→ 被占用时阻止并说明"先切换默认模型"。

#### 5.9.1 上传区（拖拽即导入）

**入口位置**（同一套组件，三处复用）
1. 模型库页顶部**常驻**上传区（任何时候都能拖）；
2. 推理页"还没有模型"空态的大号上传区；
3. 首启引导第 2 步（跳过训练直接试音色）。

**接受的东西（只认「1 个权重 + 1 个配置」）**
| 拖入物 | 处理 |
| --- | --- |
| 1 个权重（`.pth`/`.pt`/`.ckpt`）+ 1 个 `config.json` | 完整性通过 → 复制 → 进入识别 |
| 只有权重，或只有 `config.json` | **立即弹「请上传模型和配置文件」**，一个字节都不复制 |
| 权重与配置数量不是 1:1（如 2 个权重 + 1 个配置） | 同一个弹窗，副文案"一次只导入一个模型" |
| 一个文件夹 | 扫描后按上面三条判断（深度 ≤3） |
| `*.svcmodel.zip` | 先看包内是否有 1 个权重 + `config.json`（或 `manifest.json` 声明的两项）；满足才解包复制，否则同"缺配置" |
| 其他文件（图片/音频/文档） | 忽略，结果里写"已跳过 N 个非模型文件" |

**两个阶段，两个弹窗——只有这两个**

| 阶段 | 时机 | 做什么 | 不通过时 |
| --- | --- | --- | --- |
| ① 完整性 | 拖入后 ≤1s，只读文件名/大小/JSON 头部，**不读权重内容、不复制** | 判断"是否 1 权重 + 1 配置" | 弹窗 A |
| ② 识别 | 复制并校验 sha256 之后 | 跑 §5.8 的 7 步结构判定 | 弹窗 B |

**弹窗 A：请上传模型和配置文件**
- 标题：`请上传模型和配置文件`
- 正文：`当前只收到「模型文件」` 或 `当前只收到「配置文件」`（按实际缺失侧显示）；数量不对时显示 `当前收到 2 个模型、1 个配置`；第二行固定为 `导入需要 1 个模型（.pth / .pt / .ckpt）+ 1 个 config.json，一次只能导入一个模型，请把它们一起拖进上传区。`
- 按钮：`知道了`（主）/ `重新选择`（打开文件选择器，多选模式——允许一次选中模型和配置）
- 行为：关闭后上传区恢复 idle；**不产生 staging、不写数据库、不占磁盘**。

**弹窗 B：无法识别该模型**
- 标题：`无法识别该模型`
- 正文：一句话原因，从判定结果映射（示例）：
  - `权重里缺少模型必需的 enc_p 结构，可能不是 so-vits-svc 4.x 模型`
  - `config.json 不是合法的配置文件（无法解析 JSON）`
  - `config.json 与权重结构不匹配（filter_channels 维度不一致）`
  - `该模型不是 44100Hz 训练的，本版本不支持`
- 按钮：`查看详情`（展开缺失键/形状差异清单）/ `重新上传` / `删除`（默认焦点"重新上传"）
- 行为：文件移到 `models/imports/_unrecognized/<slug>/` 保留 7 天供排障，模型库不出现卡片；用户可一键彻底删除。

**交互状态**
```
idle → dragging(高亮) → checking(≤1s) → copying(字节进度) → verifying(sha256 复算)
     → recognizing(7 步判定) → ready | needs_attention | rejected
```
- `needs_attention`：识别**成功**但缺依赖资产（如缺 contentvec）——不弹窗，模型卡置灰 + "去资产中心"；
- `rejected`：识别失败 → 弹窗 B，文件在 `_unrecognized/`，不进模型库。

**完整性规则（防止"只拖了一半"）**
1. 只接受 1:1；多余文件忽略但列出来，提示"已忽略：xxx"；
2. 出现 2 个及以上权重（或 2 个及以上 config）→ 按弹窗 A 处理，副文案"一次只能导入一个模型"；
3. zip 内没有 `config.json` 且无 `manifest.json` 声明 → 弹窗 A，不解包、不复制；
4. `config.json` 存在但不是合法 JSON → 算**识别失败**（弹窗 B），因为它确实给了配置，只是坏的；
5. 判定不做模糊猜测：形状对不上就是"无法识别"，不给"强制导入"。

**复制与校验（完整性通过后才复制，源文件不动）**
1. 只有完整性检查通过才进入复制；弹窗 A 触发时磁盘占用为 0；
2. 先算总字节，检查目标盘余量（需 ≥ 总量 × 1.1 + 2GB 余量），不足直接拒绝（SVC-1006）；
3. 复制到 `models/.staging/<uuid>/`，**边复制边算 sha256**；
4. 复制完成复算一次比对（防写入损坏/U 盘掉线），不一致 → `SVC-2004` 并保留 staging 供重试；
5. 校验通过后 `os.replace` 原子移动到 `models/imports/<slug>/model/`，再跑识别；
6. 识别通过才登记数据库；识别失败则整目录改名为 `_unrecognized/<slug>/`；
7. 取消/关闭窗口：删除 staging，任务记 `cancelled`，**用户源文件始终未被修改**。

**限制与冲突**
- 单次只导入 **1 组**（1 个权重 + 1 个 config）；拖入多组 → 弹窗 A，副文案"一次只能导入一个模型"；**明确不做批量导入**（见 requirements.md §4 Backlog）；
- 非模型文件（图片/音频/说明文档）忽略并在结果里列出；**额外权重或额外 config 视为"多组"直接拦截**，不做"取第一个"；
- 单文件 ≤ 8GB；递归扫描深度 ≤3；
- 不支持从浏览器/网络地址拖入（只接受本地路径）；
- 同名模型：sha256 相同 → 提示"已在库中"并高亮原卡片；不同 → 自动后缀 `-2`；
- 磁盘写满/权限不足 → `SVC-1006` / `SVC-7001`，保留 staging 并给"换目录重试"。

**安全提示（内联，不弹第三个窗）**
- `.pth` 是 PyTorch pickle，**加载即可能执行代码**：上传区底部常驻勾选框"我确认这些模型来自可信来源"（首次默认未勾）；未勾选时拖入**不启动导入**，上传区显示红色提示条"请先确认模型来源可信"，用户勾选后可重试（SVC-6009）。
- 不做"自动解压执行"：zip 只解压数据文件，包内脚本一律不运行；包内含 `.bat/.ps1/.exe` 则整包拒绝并列出可疑条目（SVC-6010）。

**声线混合（P1）**
- 静态：2–8 个模型 + 权重，凸组合（softmax）或线性；前置校验——单说话人、`config.model` 结构一致、`spk` 映射兼容；输出 `output.pth` 并登记为新模型（标注 `mixed=true`）。
- 动态：按上游 JSON 轨道规则编辑（时间 0–1、首段从 0、末段到 1、段间首尾相接、未用角色填 `[[0,1,0,0]]`），保存前做规则校验；推理时自动置 `use_spk_mix`。

## 7. 流程与状态机

### 7.1 任务状态机

```
queued ──start──> running ──ok──> succeeded
  │                 │  │
  │                 │  ├─stop(graceful)──> stopped ──resume──> queued
  │                 │  ├─cancel──────────> cancelled
  │                 │  └─error───────────> failed ──retry──> queued
  │                 └─crash──────────────> interrupted ──resume/retry──> queued
  └─(依赖未满足)──> blocked
```

- `stopped` 只对可续训任务（训练/扩散）开放；预处理/推理的"停止"记为 `cancelled`。
- 任何状态都必须记录：开始/结束时间、exit code、错误码、产物清单、参数快照。
- 状态变更写 `job_events`（append-only），便于事后还原"到底发生了什么"。

### 7.2 一键流程（默认路径）

```
创建项目 → doctor → 资产就绪 → 导入数据集 → QC 门禁 → 切片/清洗 → 预处理三步
        → 产物校验 → 配置断言 → 100 步冒烟 → 长训（可停）→ 模型登记 → 试听/推理
```

每一步都是"门禁 + 产物"：门禁不过不进下一步；产物缺失不承认上一步完成。UI 的 7 步卡与这条链一一对应。

### 7.3 取消/停止时序（关键）

1. 用户点停止 → 编排层置任务 `stopping` → 向 worker 发送 `stop`（JSON-RPC）；
2. worker 关闭 DataLoader、flush TensorBoard、保存最后一次机会的 checkpoint（若正处保存点）；
3. 超时 5s 未退出 → 杀死 Job Object 内整个进程树；
4. 编排层校验 `nvidia-smi` 显存回落（允许 3s 抖动）；
5. 任务置 `stopped`，UI 显示"停在第 N 步"与"续训"按钮。

## 8. 交互与文案规则

1. **诚实优先**：暂停就是停止；丢步就说丢步（"最多回退 800 步"）。禁止"无损暂停""秒级恢复"等词。
2. **错误三段式**：现象（发生了什么）→ 原因（为什么）→ 下一步（点哪里）。例如：
   > 训练中断：显存不足。当前 batch_size=6 超过 6GB 显卡承载。已自动降到 3 并重试一次。
3. **破坏性操作**：删除项目/模型/覆盖配置，必须二次确认 + 说明后果 + 默认焦点在"取消"。
4. **长任务保护**：关闭窗口默认最小化到托盘（可在设置改为"询问"）；托盘图标显示进度；任务完成弹系统通知。
5. **等待可感知**：>1s 的操作必须有进度或骨架屏；>30s 的必须给"预估剩余"。
6. **不制造焦虑**：推理/训练中间态不用红色；红色只用于"失败/阻断"。
7. **可复制**：所有命令、路径、错误码都可一键复制（便于求助）。

## 9. 数据与产物

- 元数据：SQLite（WAL 模式），表结构见 [附录 C](prd/appendix-c-data-model.md)。
- 大产物：文件系统，写入一律"临时文件 + 原子改名"（`os.replace`），避免半截文件被当成可用产物。

| 单测覆盖 | Rust 核心 ≥85% 行 / Python 领域层 ≥90% / 前端关键路径 ≥80%（覆盖率为地板，不是目标） |
| 契约测试 | IPC 消息 schema 双向校验；TS 类型由 Rust 生成，禁手写重复定义 |
| 模糊测试 | 导入判定、日志解析、配置 Schema 三个解析器各跑 ≥10⁶ 次无 panic/无未捕获异常 |
| 性能回归 | 基准套件入库；任一指标相对上一版回退 >5% 阻断发布 |
| 可复现 | 同参数重跑指标一致（容差见 §5.7）；构建可重复（锁定依赖 + 固定工具链版本） |
| 文档 | 每个错误码有可复现用例；每个页面有走查记录；ADR 与实现不一致即为缺陷 |
